# SKU Auto-Generation Implementation Guide

## Overview
This document outlines the automatic SKU (Stock Keeping Unit) generation system for the Mizizzi Admin Dashboard. SKUs are now auto-generated by the backend and displayed as read-only in the admin interface.

## Changes Made

### 1. Backend Responsibility
- **SKU Generation**: The backend API (`/api/admin/products`) is now responsible for generating SKUs automatically
- **When Generated**: SKUs are generated when a product is first created
- **Format**: `PROD-{YYYYMMDD}-{PADDED_ID}` (e.g., `PROD-20260310-00079`)
- **Uniqueness**: Each product gets a unique SKU based on its ID and creation date

### 2. Frontend Changes

#### Product Pricing & Inventory Tab
**File**: `frontend/components/admin/products/product-pricing-inventory-tab.tsx`

- SKU field is now **read-only** and disabled
- Visual styling shows it as a non-editable field with gray background
- Added a **copy button** to easily copy the SKU to clipboard
- Auto-generated message displays: "Auto-generated upon save"
- Copy feedback with checkmark icon for 2 seconds

**Key Features**:

### 3. Utility Functions
**File**: `frontend/lib/utils.ts`

Added `generateSKU()` function for frontend reference:
```typescript
/**
 * Generate a SKU (Stock Keeping Unit) from a product ID and name
 * Backend-preferred format: PROD-{YYYYMMDD}-{PADDED_ID}
 * Example: PROD-20260310-00079
 * @param productId - The product ID
 * @param productName - The product name (optional, for reference)
 * @returns Generated SKU string
 */
export function generateSKU(productId: number | string, productName?: string): string {
  const id = String(productId).padStart(5, "0")
  const date = new Date()
  const timestamp = `${date.getFullYear()}${String(date.getMonth() + 1).padStart(2, "0")}${String(date.getDate()).padStart(2, "0")}`
  return `PROD-${timestamp}-${id}`
}
```

## User Experience Flow

### Creating a New Product
1. Admin navigates to "New Product"
2. Enters product name and slug
3. Clicks "Create Product"
4. Product is created with auto-generated SKU by backend
5. Admin is redirected to edit page
6. SKU is displayed as read-only field with copy button

### Editing an Existing Product
1. Admin opens product edit page
2. SKU field shows the auto-generated value
3. Admin can copy SKU using the copy button
4. Saving the product will NOT modify the SKU
5. SKU remains permanent and unique

## Backend Integration Requirements

Your backend API should:

1. **On Product Creation** (`POST /api/admin/products`):
   - Generate and assign a SKU if not provided
   - Return the generated SKU in the response
   - Store SKU in the database

2. **On Product Update** (`PUT /api/admin/products/{id}`):
   - Ignore any SKU value sent from frontend
   - Keep the original SKU unchanged
   - Return the unchanged SKU in response

3. **SKU Generation Algorithm** (Recommended):
   ```
   Format: PROD-{YYYYMMDD}-{PADDED_ID}
   Where:
   - PROD is a prefix
   - YYYYMMDD is the current date
   - PADDED_ID is the product ID padded to 5 digits with zeros
   Example: PROD-20260310-00079
   ```

4. **Database Schema** (Ensure exists):
   - `products.sku` column should be:
     - VARCHAR(20) or TEXT
     - UNIQUE constraint
     - NOT NULL
     - Indexed for fast lookups

## Migration Notes

If you have existing products without SKUs:

1. **Backfill SKUs** using a database migration:
   ```sql
   UPDATE products 
   SET sku = CONCAT('PROD-', DATE_FORMAT(created_at, '%Y%m%d'), '-', LPAD(id, 5, '0'))
   WHERE sku IS NULL OR sku = '';
   ```

2. **Verify uniqueness**:
   ```sql
   SELECT sku, COUNT(*) as count 
   FROM products 
   GROUP BY sku 
   HAVING count > 1;
   ```

## Troubleshooting

### Issue: SKU shows "Auto-generated upon save" even after saving
- **Solution**: Refresh the page to fetch the latest product data from the backend

### Issue: Copy button not working
- **Solution**: Check browser console for CORS or security policy errors
- **Solution**: Verify browser supports Clipboard API

### Issue: Duplicate SKUs in database
- **Solution**: Run the backfill migration with proper uniqueness constraints
- **Solution**: Check backend logic to ensure SKU generation is idempotent

### Issue: SKU field still appears editable in form
- **Solution**: Clear browser cache and refresh
- **Solution**: Verify the Input component has `disabled` and `readOnly` attributes
